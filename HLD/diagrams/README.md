# Diagrams

**Intentionally on hold, not just "not started yet."**

This folder will eventually hold the actual system diagrams for the designs covered in this repo—how to translate requirements, components, and API design into a coherent architecture diagram, and how to talk through it out loud the way an interview actually demands.

The reason I'm not writing conventions here yet: diagramming rules are genuinely hard to get right before you've drawn a lot of them and run into the tricky edge cases yourself. If I write down rules now, off of theory instead of repetition, I'll just end up rewriting them after the first few dozen real diagrams expose what I got wrong. I'd rather go through several rounds of real designs first, see what actually trips me up, and only then come back and write conventions worth following. Not in the mood to force that review right now, and forcing it early would just mean redoing it later anyway.
